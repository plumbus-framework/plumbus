# Form Generator

The form generator extracts form field metadata from Zod input schemas attached to capability contracts.

It produces structured form hints that UI code can consume to render labels, input types, validation hints, default values, and enum options.

The generator reads `capability.input`. It does not read entity definitions.

## Types

```ts
type FormFieldType =
  | "text"
  | "number"
  | "boolean"
  | "select"
  | "textarea"
  | "date"
  | "hidden";

interface FormFieldHint {
  name: string;
  label: string;
  fieldType: FormFieldType;
  required: boolean;
  defaultValue?: unknown;
  zodType: string;
  options?: string[];
  validation: FormValidation;
  description?: string;
}

interface FormValidation {
  min?: number;
  max?: number;
  minLength?: number;
  maxLength?: number;
  pattern?: string;
  nullable?: boolean;
}

interface FormHints {
  capabilityName: string;
  kind: string;
  fields: FormFieldHint[];
}
```

## How it works

The implementation introspects Zod schemas at runtime through their internal `_def` structure.

Only Zod object inputs produce field lists. If `capability.input` is not a Zod object schema, the returned `FormHints` object has an empty `fields` array.

## Schema unwrapping

The generator unwraps common Zod wrappers before determining the field type:

| Wrapper | Behavior |
|---|---|
| `ZodOptional` | Unwraps the inner type and marks the field as not required. |
| `ZodDefault` | Unwraps the inner type, marks the field as not required, and extracts the default value. |
| `ZodNullable` | Unwraps the inner type and sets `validation.nullable`. |

## Zod type mapping

| Zod type | Form field type |
|---|---|
| `ZodString` | `"text"` |
| `ZodNumber` / `ZodBigInt` | `"number"` |
| `ZodBoolean` | `"boolean"` |
| `ZodDate` | `"date"` |
| `ZodEnum` / `ZodNativeEnum` | `"select"` |
| `ZodObject` / `ZodArray` / `ZodRecord` | `"textarea"` |
| Other | `"text"` |

## Validation extraction

The generator reads checks from the Zod schema where available.

| Check | Extracted hint |
|---|---|
| string `min` | `validation.minLength` |
| string `max` | `validation.maxLength` |
| number `min` | `validation.min` |
| number `max` | `validation.max` |
| `regex` | `validation.pattern` with the regex source |
| `email` | `validation.pattern: "email"` |
| `url` | `validation.pattern: "url"` |

## Label generation

Field names are converted to title case:

```text
firstName   → First Name
user_email  → User Email
user-id     → User Id
```

## Functions

### `extractFieldHint(name, schema)`

Extracts one `FormFieldHint` from one schema field.

```ts
const hint = extractFieldHint("email", z.string().email());
```

### `extractFormHints(capability)`

Extracts all form hints from `capability.input`.

```ts
const hints = extractFormHints(createUserCapability);
```

Example output shape:

```ts
{
  capabilityName: "createUser",
  kind: "action",
  fields: [
    {
      name: "email",
      label: "Email",
      fieldType: "text",
      required: true,
      zodType: "ZodString",
      validation: { pattern: "email" }
    }
  ]
}
```

### `generateFormHintsCode(capability)`

Generates a TypeScript source string exporting one constant for one capability.

```ts
const source = generateFormHintsCode(createUserCapability);
// export const CreateUserFormHints = { ... } as const;
```

### `generateFormHintsModule(capabilities)`

Generates a complete source file containing form hint constants for all supplied capabilities.

```ts
const source = generateFormHintsModule(capabilities);
```

The generated file starts with:

```ts
// Auto-generated by @plumbus/ui — do not edit
```

## Generation guidance

- Treat form hints as metadata, not as final form UI.
- This generator reads capability input schemas and does not read entity definitions.
- Regenerate `form-hints.ts` when capability inputs change instead of editing it manually.
- Review generated forms for UX, accessibility, and business-specific validation before production use.
